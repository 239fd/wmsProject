Данный микросервис представляет собой сервис - работы с поставками и товаром. Данный сервис является сердцем проекта и носителем основной логики проекта. 
Среди функций необходимых к реализации:
1. Прием товара. Первоначально выбирается(если RPA, достал эти данные, это на потом)/создается поставка, далее в поставку добавляются товары (если товара нет, то создается новый), которые должны прийти (а именно наименование, плановое количество, цена за единицу), далее товары как бы фактически прибывают на склад и вносятся партии товара, на основании поставки подтягиваются данные о позициях и вводится номер партии, количество в партии, дата производства и срок годности, партий внутри одного товара может быть несколько. Далее финальным этапом является размещение товара, есть два режима: автоматический - система должна сама разместить на основании топологии склада, ручное - пользователь должен получить топологию склада и выбрать куда. В результате генерируется акт приемки товара и приходной ордер. Для каждой партии товара необходимо указать(выбрать) условия хранения, то есть молоко в холодильнике и т.п. А также создать штрих-коды со следующей логикой AAAABBBBCCCCDDDD, где AAAA - код организации, BBBB - код склада, СССС - код стеллажа, DDDD - тип стеллажа и номер ячейки/места при наличии, то естб некий SKU. И отправить это на печать в виде файла(далее сами распечатают). Если товар не помещается на складе операция отменяется.
2. Размещение товара по складу. Описано выше.
3. Перемещение товара по складу. Смена места хранения склада. Кладовщик может переместить товар в другое место хранения на складе. Данный процесс обязательно логируется в бд. SKU меняется.
4. Отпуск(отгрузка) товара со склада. Первоначально создается заявка на отгрузку товара. Указывается получатель, дата отгрузки и комментарий при необходимости. Далее в заявку добавляются товары по наименованию и количеству. Данный товар автоматически резервируется на складе. И дальнейшие операции с ним не доступны, для подбора товара используется метод FIFO по поставкам. Когда заявка была создана, необходимо ее выполнить, генерируется лист подбора(товары, SKU и их места на складе), который передается грузчику и он по нему по складу собирает товары. Когда физически грузчик принес товар к зоне отгрузки, пользователь должен внести серийный номер или SKU, штрих-код, товара и его количество. В UI будет отражаться прогресс-бар выполнения заявки. Когда заявка выполнена начинается процесс отгрузки, выбирается какая-то заявка, выбирается тип документов, вводятся необходимые параметры для генерации документов будь то ТТН, ТН, счет-фактуры, инвойс и cmr. Также для внутреннего учета склада гененрируется отпускной ордер. В конечном итоге заявка завершается.
5. Переоценка товара. Данный процесс включается в себя операцию по изменении стоимости товара. Обязательным фактором является генерация акта о переоценке, обязательным является ввод таких данных, как дата, причина переоценки, основание для переоценки, ответственное лицо, соства коммисии, ну и конечно же добавление позиций к переоценке, где автоматом подтягивается старая цена, позиции выбираются из партий поставок.
6. Проведение инвентаризации. Данный процесс включает в себя процесс проведения инвентаризации товара. Сперва создается сессия инвентаризации, в ней указывается материально ответсвтенное лицо, указывается причина инвентаризации и состав комисии. Когда создается сессия, все, что в наличии на складе на данный момент, фиксируется и далее, человек как бы ходит по складу и осуществляет ввод по sku или штрихкоду или выбирает товар. В финале создается инвентаризационная опись, а товары, которые не попали, но были зафиксированы, помечаются к списанию.
7. Списание товара. Данный процесс заключается в снятии с учета товаров. Думаю подробно расписывать не стоит, как происходит процесс, похож на переоценку. Но в результате генерируется акт о списании, а также товары, которые помечены для списания находятся в списке в начале при выборе товаров из поставок.
8. Карточка товара. Это функции возможности просмотреть весь маршрут какого-то определенного товара на складе, с момента его поступления. И при необходимости его печать.

CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

CREATE TABLE product_read_model
(
    product_id      UUID PRIMARY KEY      DEFAULT uuid_generate_v4(),
    name            VARCHAR(255) NOT NULL,
    sku             VARCHAR(100) UNIQUE,
    barcode         VARCHAR(100),
    category        VARCHAR(100),
    description     TEXT,
    unit_of_measure VARCHAR(50),
    weight_kg       NUMERIC(10, 2),
    volume_m3       NUMERIC(10, 3),
    price           NUMERIC(12, 2),
    abc_class       CHAR(1),
    organization_id UUID,
    created_at      TIMESTAMP    NOT NULL DEFAULT now(),
    updated_at      TIMESTAMP    NOT NULL DEFAULT now()
);
CREATE INDEX idx_product_org_id ON product_read_model (organization_id);

CREATE INDEX idx_product_read_model_sku ON product_read_model (sku);
CREATE INDEX idx_product_read_model_barcode ON product_read_model (barcode);
CREATE INDEX idx_product_read_model_category ON product_read_model (category);

CREATE TABLE product_events
(
    event_id      BIGSERIAL PRIMARY KEY,
    product_id    UUID        NOT NULL,
    event_type    VARCHAR(50) NOT NULL,
    event_data    JSONB       NOT NULL,
    event_version INT         NOT NULL,
    created_at    TIMESTAMP   NOT NULL DEFAULT now()
);

CREATE INDEX idx_product_events_product_id ON product_events (product_id);

CREATE TABLE inventory_events
(
    event_id      BIGSERIAL PRIMARY KEY,
    inventory_id  UUID        NOT NULL,
    event_type    VARCHAR(50) NOT NULL,
    event_data    JSONB       NOT NULL,
    event_version INT         NOT NULL,
    created_at    TIMESTAMP   NOT NULL DEFAULT now()
);

CREATE INDEX idx_inventory_events_inventory_id ON inventory_events (inventory_id);
CREATE INDEX idx_inventory_events_created_at ON inventory_events (created_at);

CREATE TABLE product_batch
(
    batch_id         UUID PRIMARY KEY   DEFAULT uuid_generate_v4(),
    product_id       UUID      NOT NULL,
    batch_number     VARCHAR(100),
    manufacture_date DATE,
    expiry_date      DATE,
    supplier         VARCHAR(255),
    purchase_price   NUMERIC(12, 2),
    created_at       TIMESTAMP NOT NULL DEFAULT now()
);

CREATE INDEX idx_product_batch_product_id ON product_batch (product_id);
CREATE INDEX idx_product_batch_expiry_date ON product_batch (expiry_date);

CREATE TABLE inventory
(
    inventory_id      UUID PRIMARY KEY        DEFAULT uuid_generate_v4(),
    product_id        UUID           NOT NULL,
    batch_id          UUID,
    warehouse_id      UUID           NOT NULL,
    cell_id           UUID,
    quantity          NUMERIC(12, 3) NOT NULL,
    reserved_quantity NUMERIC(12, 3) NOT NULL DEFAULT 0,
    status            VARCHAR        NOT NULL,
    last_updated      TIMESTAMP      NOT NULL DEFAULT now(),
    version           BIGINT         NOT NULL DEFAULT 0,
    CONSTRAINT uk_inventory_product_batch_warehouse_cell UNIQUE (product_id, batch_id, warehouse_id, cell_id)
);

CREATE INDEX idx_inventory_product_id ON inventory (product_id);
CREATE INDEX idx_inventory_warehouse_id ON inventory (warehouse_id);
CREATE INDEX idx_inventory_cell_id ON inventory (cell_id);

CREATE TABLE inventory_session
(
    session_id   UUID PRIMARY KEY     DEFAULT uuid_generate_v4(),
    warehouse_id UUID        NOT NULL,
    started_by   UUID        NOT NULL,
    started_at   TIMESTAMP   NOT NULL DEFAULT now(),
    completed_at TIMESTAMP,
    status       VARCHAR(50) NOT NULL,
    notes        VARCHAR(255)
);

CREATE INDEX idx_inventory_session_warehouse_id ON inventory_session (warehouse_id);
CREATE INDEX idx_inventory_session_status ON inventory_session (status);

CREATE TABLE inventory_count
(
    count_id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    session_id        UUID           NOT NULL REFERENCES inventory_session (session_id) ON DELETE CASCADE,
    product_id        UUID           NOT NULL,
    batch_id          UUID,
    cell_id           UUID,
    warehouse_id      UUID           NOT NULL,
    expected_quantity NUMERIC(12, 3) NOT NULL,
    actual_quantity   NUMERIC(12, 3),
    discrepancy       NUMERIC(12, 3),
    notes             VARCHAR(255)
);

CREATE INDEX idx_inventory_count_session_id ON inventory_count (session_id);

CREATE TABLE product_operation
(
    operation_id   UUID PRIMARY KEY        DEFAULT uuid_generate_v4(),
    operation_type VARCHAR        NOT NULL,
    product_id     UUID           NOT NULL,
    batch_id       UUID,
    warehouse_id   UUID           NOT NULL,
    from_cell_id   UUID,
    to_cell_id     UUID,
    quantity       NUMERIC(12, 3) NOT NULL,
    user_id        UUID           NOT NULL,
    document_id    UUID,
    supply_id      UUID,
    operation_date TIMESTAMP      NOT NULL DEFAULT now(),
    notes          TEXT
);

CREATE INDEX idx_product_operation_product_id ON product_operation (product_id);
CREATE INDEX idx_product_operation_warehouse_id ON product_operation (warehouse_id);
CREATE INDEX idx_product_operation_operation_date ON product_operation (operation_date);

CREATE TABLE product_operation_events
(
    event_id      BIGSERIAL PRIMARY KEY,
    operation_id  UUID        NOT NULL,
    event_type    VARCHAR(50) NOT NULL,
    event_data    JSONB       NOT NULL,
    event_version INT         NOT NULL,
    created_at    TIMESTAMP   NOT NULL DEFAULT now()
);

CREATE INDEX idx_operation_events_operation_id ON product_operation_events (operation_id);
CREATE INDEX idx_operation_events_created_at ON product_operation_events (created_at);

CREATE TABLE suppliers
(
    supplier_id    UUID PRIMARY KEY      DEFAULT uuid_generate_v4(),
    name           VARCHAR(255) NOT NULL,
    unp            VARCHAR(20),
    contact_person VARCHAR(255),
    phone          VARCHAR(50),
    email          VARCHAR(255),
    address        VARCHAR(512),
    is_active      BOOLEAN      NOT NULL DEFAULT TRUE,
    created_at     TIMESTAMP    NOT NULL DEFAULT now(),
    updated_at     TIMESTAMP    NOT NULL DEFAULT now()
);

CREATE INDEX idx_suppliers_name ON suppliers (name);
CREATE INDEX idx_suppliers_unp ON suppliers (unp);

CREATE TYPE supply_status AS ENUM ('PLANNED', 'IN_PROGRESS', 'ACCEPTED', 'REJECTED', 'CANCELLED');

CREATE TABLE supplies
(
    supply_id       UUID PRIMARY KEY       DEFAULT uuid_generate_v4(),
    organization_id UUID,
    supplier_id     UUID REFERENCES suppliers (supplier_id),
    warehouse_id    UUID          NOT NULL,
    status          supply_status NOT NULL DEFAULT 'PLANNED',
    expected_date   DATE,
    actual_date     DATE,
    total_items     INT           NOT NULL DEFAULT 0,
    notes           TEXT,
    created_by      UUID          NOT NULL,
    created_at      TIMESTAMP     NOT NULL DEFAULT now(),
    updated_at      TIMESTAMP     NOT NULL DEFAULT now()
);

CREATE INDEX idx_supplies_organization_id ON supplies (organization_id);
CREATE INDEX idx_supplies_supplier_id ON supplies (supplier_id);
CREATE INDEX idx_supplies_warehouse_id ON supplies (warehouse_id);
CREATE INDEX idx_supplies_status ON supplies (status);

CREATE TYPE saga_type AS ENUM ('RECEIVE', 'SHIP');
CREATE TYPE saga_status AS ENUM ('PENDING', 'COMPLETED', 'FAILED', 'COMPENSATING', 'COMPENSATED', 'COMPENSATION_FAILED');

CREATE TABLE saga_state
(
    saga_id        UUID PRIMARY KEY     DEFAULT uuid_generate_v4(),
    saga_type      saga_type   NOT NULL,
    status         saga_status NOT NULL DEFAULT 'PENDING',
    current_step   VARCHAR(50) NOT NULL,
    payload        JSONB       NOT NULL,
    failure_reason TEXT,
    created_at     TIMESTAMP   NOT NULL DEFAULT now(),
    updated_at     TIMESTAMP   NOT NULL DEFAULT now()
);

CREATE INDEX idx_saga_state_type ON saga_state (saga_type);
CREATE INDEX idx_saga_state_status ON saga_state (status);
CREATE INDEX idx_saga_state_created_at ON saga_state (created_at);

CREATE INDEX idx_supplies_supplier_id ON supplies (supplier_id);
CREATE INDEX idx_supplies_warehouse_id ON supplies (warehouse_id);
CREATE INDEX idx_supplies_status ON supplies (status);
CREATE INDEX idx_supplies_expected_date ON supplies (expected_date);

CREATE TABLE supply_items
(
    item_id      UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    supply_id    UUID           NOT NULL REFERENCES supplies (supply_id) ON DELETE CASCADE,
    product_id   UUID           NOT NULL,
    expected_qty NUMERIC(12, 3) NOT NULL,
    actual_qty   NUMERIC(12, 3),
    unit_price   NUMERIC(12, 2),
    notes        VARCHAR(255)
);

CREATE INDEX idx_supply_items_supply_id ON supply_items (supply_id);
CREATE INDEX idx_supply_items_product_id ON supply_items (product_id);

CREATE TABLE planned_deliveries
(
    delivery_id       UUID PRIMARY KEY      DEFAULT uuid_generate_v4(),
    external_id       VARCHAR(100) NOT NULL UNIQUE,
    supplier_name     VARCHAR(255),
    product_name      VARCHAR(255),
    expected_quantity INT,
    expected_date     DATE,
    warehouse_id      UUID,
    source            VARCHAR(50),
    extracted_at      TIMESTAMP    NOT NULL DEFAULT now(),
    processed         BOOLEAN      NOT NULL DEFAULT FALSE
);

CREATE INDEX idx_planned_deliveries_external_id ON planned_deliveries (external_id);
CREATE INDEX idx_planned_deliveries_expected_date ON planned_deliveries (expected_date);

CREATE TABLE extraction_log
(
    log_id        BIGSERIAL PRIMARY KEY,
    source        VARCHAR(50) NOT NULL,
    extracted_at  TIMESTAMP   NOT NULL DEFAULT now(),
    records_found INT,
    records_new   INT,
    success       BOOLEAN     NOT NULL,
    error_message TEXT
);

CREATE INDEX idx_extraction_log_source ON extraction_log (source);
